Fix 2 — Copilot Panel Resize (Stale-State Bug)
fix Resize handles work without dragging panel first (stale-state fix) 3ab10bd → 047dade
Problem
Resize handles on the copilot panel did nothing on first drag. You had to drag the panel first, then resize would work.

Root Cause (commit 047dade)
panelPos was null on first render (panel used width:'100%' positioning). The onPointerMove handler used the functional setState form p => p ? {...p, x, y} : null which short-circuited to null when the previous state hadn't propagated yet (stale closure from batched onPointerDown update), reverting the anchor.

Fix
Changed to a plain setter () => ({x, y}) that ignores previous state and writes directly from dragRef.current values captured synchronously in onPointerDown. React render timing no longer matters because we don't read panelPos inside the setter. 
// Before — stale closure kills first drag
setPanelPos(p => p ? { ...p, x: newX, y: newY } : null)
//              ↑ p is null from the previous render → returns null → panel snaps back

// After — write directly from ref, ignore current state
setPanelPos(() => ({ x: dragRef.current.startX + dx, y: dragRef.current.startY + dy }))
//           ↑ ref is always current — no stale closure risk
Fix 3 — TTS / Voice Output Timeout
fix TTS timeout — test.setTimeout inside describe vs body; copilot warmup 60s→20s 1ab77ff · 9475db5
Problem — TTS Test Timeout
The copilot voice (TTS) E2E test was timing out at 150s even though test.use({ timeout: 300_000 }) was declared inside the describe block. TTS generation on Railway can take 45–90s, so 150s was too tight when Railway was cold.

Root Cause
test.use() inside a describe block is a static configuration call — it sets a default but does NOT override the global timeout for individual test bodies. Only test.setTimeout() called inside the test body actually changes the live running timeout.

Fix
  • Added test.setTimeout(300_000) as the first line inside each TTS test body — overrides the global 150s at runtime
  • Reduced beforeEach warmup from 60s → 20s: 60s × 4 tests × 2 workers = 8 extra minutes of dead time, causing Railway to cool down between test groups and making subsequent tests flaky
// Before — timeout set in describe scope (ignored at runtime)
describe('copilot voice', () => {
  test.use({ timeout: 300_000 }) // ← doesn't override running test body
  test('generates TTS audio', async ({ page }) => { ... })
})

// After — timeout set inside test body
test('generates TTS audio', async ({ page }) => {
  test.setTimeout(300_000) // ← actually overrides the live 150s budget
  ...
})

Journey: 5 Iterations to Reliable Audio Playback

Audio playback went through 5 rapid iterations over 2 days as each fix exposed a new browser policy constraint. The final design is native HTML5 <video> audio — no Web Audio API interception.


fix Iteration 1 — video/audio silent: call play() inside click gesture, not rAF 578dab1
Problem
Entire editor was silent — no video audio, no music, no voice.

Root Cause
HTMLMediaElement.play() was called from inside a requestAnimationFrame callback. Browsers only allow audio to start if play() is called directly inside a user-gesture event handler (click, keydown). rAF fires after the event returns — too late.

Fix
Moved video.play() and audio.play() into the synchronous startPlay() function called directly from the click handler. rAF tick continues to handle drift correction and seek-bar updates only. 
// Before — play() inside rAF → browser blocks (not a user gesture)
requestAnimationFrame(() => { video.play() })

// After — play() directly in click handler → gesture satisfied
button.onclick = () => { startPlay(); }
function startPlay() { video.play(); audio.play(); }
feat Iteration 2 — Web Audio API routing via AudioContext + GainNode a72a5b2
Why tried
Browser autoplay policy also applies to the element's output. Even when play() succeeds inside a gesture, some browsers muted the element's audio if it was created outside the gesture. Web Audio API fixes this by wiring the video through an AudioContext (created inside the gesture) so the audio graph is unlocked.

Approach
Created AudioContext + createMediaElementSource(videoEl) + GainNode inside the click handler. GainNode.gain.value used for volume/mute instead of video.muted.
fix Iteration 3 — Revert Web Audio API: caused total silence on any graph error 2262eae
Regression
createMediaElementSource() intercepts the video element's native audio routing. If the AudioContext or GainNode had any issue (CORS on the signed R2 URL, suspended context, node disconnected), the result was complete silence — and the native HTML5 routing was also broken because it was already intercepted.

Final decision — revert to native
  • Web Audio API removed entirely
  • <video> element carries its own audio — v.muted / v.volume for control
  • Linked AUDIO track clips still appear in the timeline for visibility, but don't create a separate <audio> element
  • Linked AUDIO clips now show label "Audio" (not the video filename)
feat Iteration 4 — Detach Audio: extract MP3 from video via ffprobe + ffmpeg e2844a0
"Detach Audio" button in track controls calls POST /editor/:id/media-bin/:assetId/detach-audio. Backend runs:
ffmpeg -i input.mp4 -vn -acodec libmp3lame -q:a 2 output.mp3
Result is stored as a new AUDIO asset in the bin and added to the timeline as an independent AUDIO clip. User can then independently trim, loop, or replace the audio.
fix FFmpeg export — adelay format + audio from composite.mp4 6406819
Two FFmpeg audio crashes in the export pipeline

Crash 1 — "Stream specifier matched no streams"
Second FFmpeg pass tried to pull audio from each raw video segment. But segments on disk have no separate audio stream — their audio is embedded. The second pass couldn't find the stream and aborted.
Fix: Second pass reads [0:a] from composite.mp4 (first-pass output which already has embedded audio). No per-segment re-reads.

Crash 2 — adelay channel format
adelay=100|100 syntax (per-channel delays) fails on mono audio streams. The newer, universal format is required:
adelay=100|100            ← fails on mono
adelay=delays=100:all=1   ← applies to all channels universally
fix Social import: pass ffmpeg-static path to yt-dlp for stream merging 4d68cff
Problem
Videos downloaded from YouTube/Instagram were arriving as audio-only .m4a files. Video track was missing entirely.

Root Cause
yt-dlp downloads separate video + audio streams and merges them using ffmpeg. Without --ffmpeg-location, it falls back to audio-only because it can't find the ffmpeg binary.

Fix
ffmpeg-static is already a npm dependency — its default export is the absolute path to the binary. Forwarded this path:

ytDlpArgs.push('--ffmpeg-location', ffmpegPath);

Architecture Overview

Sozialzynk uses Cloudflare R2 as the primary object storage for all media assets. R2 is S3-compatible but with no egress fees — critical for a video-heavy platform.


What's stored in R2

  • Uploaded videos (SHORTS_SOURCE_VIDEO, VIDEO)
  • Extracted audio MP3s (AUDIO)
  • Generated voice assets (VOICE)
  • AI-generated music tracks (MUSIC)
  • Uploaded images (IMAGE)
  • Exported render files (EDIT_RENDER)

R2 key structure

  • uploads/{userId}/{assetId}/original.mp4
  • voices/{userId}/{assetId}/voice.mp3
  • renders/{editId}/{versionId}/output.mp4
  • music/{trackId}/track.mp3
  • Prefix-based: all files for one asset share a prefix
Signed URL Flow
feat How R2 signed URLs work in the editor architecture
R2 bucket is private — no public access. All asset access goes through signed URLs: 
// 1. Backend generates a short-lived signed URL (1-hour TTL)
const url = await storage.getSignedUrl(r2Key, { expiresIn: 3600 });
// e.g. https://<accountid>.r2.cloudflarestorage.com/uploads/.../original.mp4?X-Amz-Signature=...

// 2. API returns the signed URL as part of the MediaBinEntry
{ id: "xxx", label: "promo.mp4", url: "https://...r2...?X-Amz-Signature=..." }

// 3. Frontend uses the signed URL in <video src> directly
<video src={entry.url} />

// 4. Export renders download via proxy route (not direct R2)
GET /api/proxy/media/versions/:versionId/file
// → backend calls storage.getSignedUrl() fresh and 301-redirects to R2
The export proxy route was needed because the renderVersionId → R2 key mapping lives server-side and the signed URL must be generated per-request (can't bake a short-lived URL into a download button).
Hard-Delete on Bin Remove (commit 549f1d3)
feat lock/unlock working files + hard-delete from Cloudflare R2 on remove 549f1d3
Problem
Deleting a file from the Media Bin only removed the DB record. The actual video file stayed in R2 forever — storage costs would accumulate indefinitely.

Hard-delete pipeline 
// removeFromBin service (editor.service.ts)
async removeFromBin(editId, assetId, userId) {
  const asset = await db.asset.findFirst({ where: { id: assetId } });
  if (asset.locked) throw new ForbiddenException('Asset is locked');

  // 1. Soft-delete DB record
  await db.asset.update({ where: { id: assetId }, data: { deletedAt: new Date() } });

  // 2. Hard-delete all R2 files under the asset's key prefix
  await storage.removePrefix(`uploads/${userId}/${assetId}/`);
  // removes original.mp4, thumbnail.jpg, any derivative files
}
Lock system
New PATCH /editor/:id/media-bin/:assetId/lock endpoint toggles the locked flag. Locked assets:
  • Cannot be deleted — removeFromBin throws 403 Forbidden
  • Show a lock badge in the Media Bin UI
  • Delete button is disabled with a tooltip explaining why
